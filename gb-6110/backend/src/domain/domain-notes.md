# 离线回网的养护副本点验

青徊园护的 12 人组用离线终端记录行道树养护。人工点验需要下载两份全量清单，逆序导出会干扰简单文本比较，终端记录较旧时也很难区分业务冲突与滞后修订。上游为主账和同一截止时点的终端快照，下游为负责补录和人工追查的核对员。

主账和巡养终端常在不同时间留快照，交班时凭变更流水把较晚一侧回退到较早的截止时点再比对。同一树号迁走一棵又补栽一棵，修订号会从 1 重计；回退按流水号逆序套用 before/after 完整记录，不靠修订号推断，也能还原当时那条养护记录。变更记录乱序送到不影响结果；流水缺号、重号或前后值对不上时，运行结果标出缺口并暂缓出单。缺口补齐后在原批次补缺续跑，核查单标明比对时点和所用流水范围，后到的记录不能改变已出的单。

08:30 终端离线快照；09:10 主账快照；09:12 登记交班批，流水乱序送达；09:15 提交分段点验，主账按流水 41–44 回退到 08:30；09:18 下载核查单。另一批缺 43 号流水，暂缓出单；09:40 补录缺失流水，原批次续跑出单。

每个叶区间由固定键域推导，输入顺序不影响摘要。叶以按树号排序的规范 JSON 计算 SHA-256，两个子摘要带类型前缀合并为父摘要。只对摘要不同的叶逐键比较。构树会读完双方输入，比较摘要的计数仅表示已建树后的递归比对开销。演练使用同一应用中提供的两份快照，MySQL 保存记录与证据，不连真实主从，也不自动修复终端数据。
